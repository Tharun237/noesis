# Noesis status-message audit

Date: 2026-10-11. Scope: every user-visible status, progress, ETA, error and toast string in `src/ui/*.jsx`, `src/App.jsx`, `src/main.jsx`, and the conditions behind them in `src/lib/*.js` and `src/ingest/*.js`.

Rule applied (product owner): a status message must be (1) TRUE at the moment it is shown, and (2) about something the user is actually waiting on or needs to act on. Two facts shown together must never look contradictory. Routine background work that blocks nothing should be silent.

Method and limits: static reading of source, line by line. No browser run was done, so runtime claims come from the code path. Items marked "estimate" or "unverified" need a check on a device before anyone acts on them.
